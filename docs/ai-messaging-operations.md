# 运行类命令的异步决定

参与者受控重试、评测启动和评测取消复用原路径、权限与业务规则，发送 `command_id`。MQ 模式的 HTTP 202 只表示 QS 已保存操作，不表示 AI 接单。创建、准备、审核、定稿和未知调用人工处置沿用原接口。

页面发送前将原命令 ID、目标、版本、理由和确认意图保存在原账号的 sessionStorage。202、超时、认证刷新及页面重载不会生成新 ID 或重发写请求。新写请求在提交前就标记为 MQ 待确认，避免超时后把任务最新版本误当作原命令回执。

页面只查询当前 QS 的固定 `/internal/v2/interpretation/ai-workflow/operations/{command_id}`，不跟随响应中的任意 `status_url`。自动查询从 1 秒退避至最多 5 秒，最多 60 秒，每次请求上限 5 秒。结束自动等待仍保留意图，可手动查询；卸载后忽略晚到查询结果。

- 发布状态与接单决定分开。`submitted` 或 `awaiting_receipt` 不能展示为已接单。
- 持久拒绝必须绑定原命令及目标，才解除待确认状态；再次操作前重新读取当前权限、容量和任务状态。
- 技术挂起保留原身份和意图，不自动获准新增模型调用。
- 接单后仍核对回执、版本和原冻结配置；取消还核对原操作人、理由、源版本及保留证据意图。超出 JavaScript 安全整数范围的版本不会被舍入后采用。
- 新 MQ 命令查询失败时不根据任务最新版本推断决定。迁移前没有 MQ 标记的旧记录仍可使用原回执读取分支；不自动重放写请求。

独立 `AI messaging UI isolated` 门禁仅验证候选分支，不触发 `Production Deploy`。测试报告必须非空且零失败、零跳过，并包含原身份、202、超时刷新、挂起、取消意图、冻结配置和版本风险场景。正常镜像使用原 `build/Dockerfile`；镜像构建和页面测试不替代真实浏览器或生产业务验收。

发送端投递达到技术预算时，操作仍可为 `status=submitted, transport_status=held`，没有 AI 决定或回执。页面停止自动轮询并明确显示“投递已技术挂起，尚未取得 AI 接单决定”，保留原意图与编号；刷新后只读原操作，不改成已接单、不生成 UUID、不再次 POST。它与持久 `decision=held` 的接单回执分别显示。
