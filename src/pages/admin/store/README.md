# 门店管理与医生配置

第一阶段仅供总部管理员维护门店与医生归属。菜单使用现有 `org_admin` 能力；QS 应用入口仍检查可信管理员能力与公司范围。

- 门店支持创建、编辑、启用和停用，不提供删除。编号创建后不可修改。
- 当前有关联医生的门店不能停用，包括已停用医生；通过关联医生列表先完成调整。
- 医生首次补配门店保留二维码，真正调店永久失效旧二维码。医生与受试者关系、已有受试者及测评不会自动迁移。
- 配置表单读取最新医生版本并保存请求标识。冲突后关闭表单并刷新，不自动覆盖他人的修改。
- 永久失效入口展示原因，不能重新启用；在医生详情按需创建新入口。
- 旧医生响应没有门店字段时显示未配置；缺少配置版本时不允许提交配置。

部署顺序：QS 的迁移和全部写入实例更新完成，再发布本前端。发生过调店后，不能退回忽略永久失效字段的后端版本；应保留后端拒绝旧码的行为并向前修复。

本阶段不实现受试者门店归属和 Assignment Scope，也不修改医生工作台的既有访问模型。

## 从门店批量配置医生

门店列表点击“管理医生”，默认展示未配置门店的医生。可搜索姓名或编号、跨页勾选，也可切换到“从其他门店调入”；“本门店医生”用于查看当前成员及打开详情、配置历史。

点击“预览变更”核对逐人原门店、目标门店和二维码影响，填写配置原因后提交。首次配置保留旧码，调店永久失效旧码。批量操作复用单人配置接口，逐人提交，版本冲突不自动覆盖；成功项不会因其他项失败而回滚。按逐人结果处理失败项，网络结果不明时先核对配置历史，再刷新选择。提交期间保持页面打开。

停用门店不能加入医生；不提供清空医生门店或删除关联，转出需从目标门店调入或使用医生详情页调整。
